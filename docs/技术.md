# 技术说明

写给「想知道每一步到底在干什么」的人。每节先说**做什么**，再说**为什么**。

## 1 一次运行的完整链路

```
bench.py stage1
  ├─ 读 config.json → 选臂 → 建 profile（setup 已完成）
  ├─ 每臂起一个记账代理 usage_proxy.py（端口 = arms.<臂>.proxy_port）
  ├─ 生成 route 覆盖层：runs/_overlays/<臂>_<端口>.route.yml（把 baseURL 指到本机代理）
  ├─ 每（臂, 题, 遍）起一次 headless 会话：
  │    dsh --profile <臂profile> --patch overlays/common.patch.yml --patch <臂覆盖层>
  │        --patch <route覆盖层> --json "<题面>"
  │    工作目录 = 随机 ID 的空目录，题面里的 workspace 已拷进去
  ├─ 会话结束：抓 usage（代理侧逐次记录）→ 写 attempts_*.jsonl
  ├─ 隔离检查：工作目录里不能出现答案/题号/别的运行痕迹
  └─ 判分（grading: after 时留到 grade 命令）
```

## 2 脚本职责

| 文件 | 职责 |
|---|---|
| `bench.py` | 主编排：参数解析、臂配置、并发调度、金丝雀核对、调用下面这些脚本 |
| `run_bench.py` | 单次运行：拼命令行、设环境变量、超时、抓日志；可单独用来调试一题 |
| `usage_proxy.py` | 记账代理：OpenAI/Anthropic 兼容转发，逐次记录 cache_hit/cache_miss/output token、耗时、错误码 |
| `grade.py` / `grade_runs.py` | 判分器：mcq / exact_int / ssb_cells / lcb_* / polyglot_* / self_* 各类题；后者按目录批量评 |
| `analyze.py` | 配对统计：题级 bootstrap、McNemar、费用比区间，输出 report.md |
| `scorecard.py` | 多维评分卡（radar + 条形），`--demo` 可看假数据样式 |
| `preset_fidelity.py` | 保真核对：把「预设应有的样子」和「覆盖层合成出来的样子」逐行比 |
| `isolation.py` | 隔离层：随机目录、断网变量、工作区准备、JS 题共享依赖注入 |
| `leakcheck.py` | 泄漏自检：扫工作区里是否出现答案/题号/测试名等不该出现的词 |
| `prompting.py` | 提示词组装：通用约束 + 8 种交付要求，各臂完全一致 |
| `answers.py` | 答案打包/解包（`tasks/_answers.bin`，避免答案明文躺在题目目录里） |
| `sample_size.py` | 预跑后的样本量/方差估计，决定跑几遍够 |
| `calibrate.py` | 用预跑数据校准难度权重 |
| `sanitize_tasks.py` | 清洗题面：去掉题源痕迹、统一换行与编码 |
| `build_public.py` / `gen_selfmade.py` / `build_hard2.py` | 从公开数据集构建题目 / 生成自建题 / 生成难题批次 |
| `selftest.py` | 自检：判分器对已知答案的回归测试 |
| `audit_*_exec.py` | 审计：编程题的隐藏测试是否真的能跑、办公题的核对脚本是否可信 |
| `check_tasks.py` | 题目包自检：manifest.csv / manifest.jsonl / tasks/ / `_answers.bin` / workspace 清单五方一致（不联网、不跑模型，可进 CI） |
| `integrity.py` | `runs/` 调试工具：把写坏的 jsonl 行摘出来备份（`*.bad`），并统计各臂各遍覆盖与 status 分布 |
| `mock/` | 离线排练：假 API、假 dsh，用来在没有额度时验证整条链路 |

## 3 文件与数据格式

```
runs/
├─ _setup/profiles.json                 每臂的 profile 名（随机生成，映射只在这里）
├─ _overlays/<臂>_<端口>.route.yml       每次运行生成的 baseURL 路由层
├─ attempts_<臂>_r<遍>_s<槽>.jsonl       每次运行的原始记录（一题一行）
├─ results_<臂>_r<遍>_s<槽>.jsonl        判分后的结果
├─ usage_<臂>_r<遍>.jsonl                代理侧的逐次用量
└─ _logs/<ID>/                           会话日志、启动失败原因、工作目录（keep_workdirs: move）
```

一条 attempts 记录的关键字段：`task_id / rep / slot / status / exit_code / wall_s / session_dir / usage{hit,miss,out}`。
一条 usage 记录：`ts / port / model / stream / cache_hit / cache_miss / output / ms / status`。
三个 token 口径都从 usage 汇总，费用按 `pricing_cny_per_mtok` 重算。

### 3.1 task.json 字段

160 道题的 `task.json` 是**同一套顶层字段 + 题型附加字段**（机器校验见 `bench/check_tasks.py`）。
注意字段名是 `task_id` / `grader`，不是 `id` / `grade` —— 外部脚本按后者写会直接 KeyError。

| 字段 | 出现范围 | 说明 |
|---|---|---|
| `task_id` | 全部 160 | 目录名，也是 `manifest.csv` 的行键 |
| `dimension` | 全部 | 编程 / 长任务注意力 / 日常办公 / 知识 |
| `source` / `source_id` | 全部 | 题源与题源内 ID（自建题为 `self`） |
| `license` | 全部 | 见 `THIRD-PARTY-DATA.md`；非商用与仅研究题在 README 第 10 节单独标注 |
| `stratum` / `role` | 全部 | 分层（选题用）与 `main` / `reserve` |
| `grader` | 全部 | 18 个判分器之一，名单由 `bench/grade.py` 的 `GRADERS` 决定 |
| `prompt` | 全部 | 题面本体（模板变量在 `bench/prompting.py` 里拼） |
| `timeout_s` | 全部 | 单题墙钟上限（600–2400 秒，取值 600/1200/1500/1800/2400）；超时记 `status=timeout`，按答错进分母（审计 R4） |
| `test_files` | 编程题（polyglot / lcb） | 隐藏测试文件名，判分时从 `_answers.bin` 解出 |
| `answer_sheet` / `answer_position` | `ssb_cells` | 工作表与判分区域；**13 题 `answer_sheet` 为 null、3 题区域串丢了开头引号**（靠 strip 兜住，见审计 P2-9） |
| `repo_chars` | 18 道 needle | 仓库字符数；`long-chain-*` 缺这个字段（审计 P2-6） |
| `context_chars` | 17 道 lb2 | 长文字符数 |
| `batch` | 24 道 hard2 | 生成批次；csv 里有、部分 task.json 没有 |

`manifest/manifest.csv`（160 行 + 表头）是唯一权威索引，`manifest.jsonl` 与 `tasks/` 由它派生。
`manifest/workspace_files.json` 记录每题 `workspace/` 的文件清单；空目录里放了一个 `.gitkeep`，
否则 zip 与 git 都不保留空目录 —— v1.5 曾因此丢掉 24 道知识题的工作目录。

## 4 覆盖层机制

命令行 `--patch` 是**叠在默认组合包之上**的改动，按行 id 覆盖：

- `overlays/common.patch.yml`：各臂共用（固定模型、关会话日志上传、关联网工具）
- `overlays/standard.patch.yml`：std 臂（补子代理的 modelSelection/modelDiscovery）
- `overlays/native-ptc.patch.yml`：ptc 臂（关原生执行器、开 PTC 执行器、停用 workflow 两行）
- `runs/_overlays/*.route.yml`：每次自动生成，把模型 baseURL 指到本臂的记账代理

`config.arms.<臂>.expect` 是「金丝雀」：建会话前把合成后的配置读出来，逐条断言——有没有 persona 规则、工具面是不是 PTC、某行有没有/不该有某个参数。断言失败即判该臂不可信，直接停。

## 5 排错顺序

1. `doctor`：Python 依赖、dsh 可执行、版本 pin、端口占用、磁盘
2. `setup` 是否建好 profile（`runs/_setup/profiles.json`）
3. `smoke`：2 道题跑通再上量
4. 单题复现：`python bench/run_bench.py --arm ptc --task <task_id> --rep 0`
5. 看 `runs/_logs/<ID>/`：里面是 dsh 的原始 stdout/stderr
6. 供应商问题：代理日志里 429/503 的分布、`provider_fail_threshold` 是否触发
7. 判分问题：`grade --regrade --prefix <前缀>`，旧结果自动备份
