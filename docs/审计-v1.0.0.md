# DSH-Bench v1 审计报告（2026-11-10）

对象：`dsh-bench-v1.9.1-public.zip`（2653 条目，解包 30 238 582 B，**168** 道题：main 110 + reserve 58）。
方法：4 个只读子审计（判分统计 / 任务数据 / 运行隔离 / 安全许可文档）+ 本机实测（WSL2、Python 3.14、dsh 0.2.2-rc.1）。
实测项：全量 `selftest`（161 题，0 problems）、`check_package`（通过）、泄漏自检、`doctor`、`setup/smoke`（真实 4 次运行）、
`preset_fidelity`（空 dump 与真实 dump）、`grade_runs` 重复 rid、`sample_size --sims 400`。

## 0. 结论

**内容层面是扎实的**：168 题三方一致（manifest.csv / manifest.jsonl / tasks/）、答案桶 168/168、workspace 清单与磁盘一致、
40 个 xlsx 全部可读、161 道题的「空答卷必须判错」成立、41 道 mcq 的 gold 全在合法选项内。
**问题集中在两处**：① 公开化的工程外壳（许可、说明、写死本机路径、答案键）；② **统计口径**——三处会把噪声变成结论。

## 9. 1.1.0：受限题目改为「只披露题号，不发布题面」

起因：原本的处理是「保留 C-Eval 8 道 + 在文档里注明非商用」。这条不成立——

| 层面 | 问题 |
|---|---|
| NC 管的是使用者 | 企业内评、厂商发布材料、云厂商选型都算商业使用；DeepSeek 自己引用分数更算。 |
| SA 更硬 | 我们改过题面（裁子集、重排选项），属改编 → 8 道必须按 BY-NC-SA 发，和仓库整体 CC0/MIT 打架；衍生题单也继承。 |
| 披露 ≠ 许可 | `THIRD-PARTY-DATA.md` 写清条件只解决「不被误导」，不解决「有权这么用」。 |

落地方式（已实现并验证）：

| 项 | 做法 |
|---|---|
| 仓库里放什么 | `manifest/upstream.json`：数据集、HF 修订号 `617524a0`、逐题 `source_id` 与 `task.json` 的 sha256 |
| 怎么拿回题 | `bench/fetch_data.py --provider ceval`：datasets-server 行接口（纯标准库）+ 逐题哈希校验 |
| 误提交防护 | `.gitignore` 排除 `tasks/know-ceval-*/`；`check_tasks.py` 抓回后只提示、不判不一致 |
| 答案 | 抓回时由数据集官方 `answer` 字段本地生成，再 `answers.py pack`；仓库的桶里不含这 8 道 |
| 规模变化 | 直接可跑 160 道（104 主测 + 56 候补）；168 道 = 160 + 抓回的 8 道 |
