# 设计说明

## 1 目标

回答一个问题：**换工具面（或换预设）能不能在不掉正确率的前提下省钱？**

为了能回答，题必须是**客观可判**、**便宜**、**覆盖面够**，并且让两臂在完全相同的条件下作答。

## 2 题目构成（104 道主测 + 56 道候补）

| 维度 | 题数 | 来源 | 判分方式 |
|---|---|---|---|
| 编程 | 38 | LiveCodeBench v6（2025-01~04 新题）23 + Aider Polyglot（Python 10 / JavaScript 5）15 | 隐藏测试全部通过才计 1 分 |
| 日常办公 | 25 | SpreadsheetBench Verified-400 15 + 自建办公文件任务 10 | 单元格级比对 / 脚本核对输出文件 |
| 知识 | 8 | MMLU-Pro 8（C-Eval 的 6 道按上游许可只披露题号，用 `bench/fetch_data.py` 抓回） | 选项字母完全一致 |
| 长任务注意力 | 33 | 自建「大仓库找信息」9 + 自建「长链路多步指令」12 + LongBench v2（short）12 | 整数完全一致 / 检查项全过 |

候补 56 道同源同分层，预跑出现坏题或全对/全错题时按顺序补位。

> GPQA Diamond 是门控题：需要在 Hugging Face 上同意条款并配 `HF_TOKEN`，用 `run.sh gpqa` 现场生成。未生成时知识维度就是 14 道——不影响配对比较（两臂同样少这 6 道），只是知识维度的绝对精度更低。

## 3 判分规则

| grader | 判什么 |
|---|---|
| `mcq` | 选项字母完全一致（允许「答案是 B」这类包装） |
| `exact_int` | 整数完全一致（允许千分位、单位后缀） |
| `ssb_cells` | 指定区域的每个单元格的值（只比值，不比数字格式；见审计 P3-5） |
| `lcb_stdio` / `lcb_functional` | 隐藏用例逐个跑；stdio 题吃 stdin/stdout，functional 题按函数签名调用 |
| `polyglot_python` / `polyglot_javascript` | 放入隐藏测试（pytest / jest）全过才算对 |
| `self_*` | 自建办公题的核对脚本（CSV/JSON/INI/xlsx/目录结构）与多步指令的逐项检查 |

判分器本身也有回归测试（`selftest`）：给定已知答案，判分器必须给出预期结论。改判分器后请先跑它。

## 4 配对与统计

- 同一题、同一 `seed`、同一提示词模板；各臂在同一随机题序上**错开起点**，避免「同一时刻做同一道题」（env 隔离下相邻工作目录可读，且同前缀题会互相预热 prompt cache）。
- **主指标**：正确率差 Δ 的 95% 置信区间（题级配对 bootstrap，默认 1000 次重采样）。下限 > −`margin`（默认 5 个百分点）才算「不掉分」。
- **配对检验**：McNemar 精确检验，看不一致对（A 对 B 错 / A 错 B 对）的分布。
- **费用**：代理逐次记录三类 token，按 `pricing_cny_per_mtok` 重算；一律按高峰价折算，避免某个臂恰好跑在半价时段占便宜。
- 样本量：`pre` 预跑后用 `sample_size.py` 估计「跑几遍才能把区间压到 ±3 个百分点内」，默认 3 遍。

## 5 公平性与防作弊

| 措施 | 做法 |
|---|---|
| 随机化 | 工作目录随机 ID、题序每遍重随机、臂的起点错开 |
| 断网 | 环境变量断掉外网（`isolation: env`）；需要严格隔离用 `docker`，只挂载本题目录、只放行记账代理 |
| 信息隐藏 | 题面里没有题号、没有来源名、没有「你在被测」这类话；答案打进 `tasks/_answers.bin`，不落在工作区 |
| 泄漏自检 | 运行后扫工作目录，出现答案/题号/数据集名/benchmark 字样即判失败 |
| 金丝雀 | 建会话前核对合成配置，确认这一臂真的是目标形态（防「覆盖层被静默忽略、两臂其实一样」） |
| 工具链一致 | 同一个 DSH 版本（`dsh_version_pin`）、同一模型版本（`model_version_expected`），不一致直接停 |
